## 1. 전환 배경 — 왜 방향을 바꾸는가

### 1.1 이전 기획(v1)과의 관계

v1은 「행정서사(行政書士) 업무 전 분야를 다루는 종합 미디어」로, **운영자 자신의 미래 행정서사 개업을 위한 집객 자산**이 최종 목적이었다. 이 구조는 두 가지 제약을 안고 있었다.

1. **자격 취득 전 법적 제약이 크다.** 행정서사법 제19조상 「개별 상담・서류작성 대행을 시사하는 표현」을 항상 피해야 했고, 이는 콘텐츠 설계・CTA・수익화 전부에 제약으로 작용했다(v1 `docs/06_LEGAL_COMPLIANCE.md` 참조).
2. **자격 취득이라는 장기 전제에 사업 전체가 종속됐다.** 시험 합격(2027년 예정)이 로드맵의 핵심 마일스톤이었다.

v2(본 문서)는 **정보 큐레이션 자체를 사업으로 본다.** 보조금・조성금 정보는:
- 발신 주체가 이미 관공서(국가・지자체)이므로 **원본 정보 자체에 권위가 있다** — 미디어의 역할은 「찾기 쉽게, 비교하기 쉽게, 최신으로」 정리하는 것.
- 개별 신청 대행이 필요 없는 영역(정보 제공만으로 독자 가치가 완결)이라 **법적 리스크가 구조적으로 낮다.**
- **자격 취득 여부와 무관하게 지금 바로 완전한 사업으로 성립한다.**

### 1.2 포지셔닝 스테이트먼트

> 국가・지자체가 흩어놓은 보조금 정보를 **지역별로 비교 가능한 형태**로 재구성하고,
> **신청 마감・조건 변경을 최속으로 갱신**하여, 「내가 받을 수 있는 보조금이 무엇인지 5분 안에 아는」 사이트가 된다.

### 1.3 차별화 축

| 축 | 내용 | 경쟁사가 못 하는 이유 |
|---|---|---|
| **① 지역 횡단 비교** | 같은 목적(예: 출산・창업)의 보조금을 **지자체별로 나란히 비교**하는 표를 제공 | 지자체 공식 사이트는 자기 지역만 다룸. 민간 매체 다수는 특정 지역(도쿄 23구 등) 또는 특정 분야(예: 助成金 보조금 전문 노무사 블로그)에 국한 |
| **② 국가・광역 API 기반 최신성** | jGrants 등 공식 API로 **募集中・締切**을 상시 감시, 공고 직후 반영 | 개인 블로그・수작업 정리 사이트는 갱신이 느리고 마감 놓친 정보가 방치됨 |
| **③ 순수 정보 제공 — 낮은 진입장벽** | 자격업 제약이 없어 **비교・체크리스트・진단 툴을 제약 없이 설계** 가능 | 士業(행정서사・노무사) 계열 미디어는 개별 상담 유도가 목적이라 비교・객관성보다 자기 사무소 CTA가 우선됨 |

## 2. 시장 환경 분석 (2026년 9월 기준)

### 2.1 보조금・조성금 시장의 구조

일본의 공적 지원금은 크게 3계층으로 나뉜다.

| 계층 | 예 | 정보 발신처 | 갱신 빈도 |
|---|---|---|---|
| **국가** | 事業再構築補助金, ものづくり補助金, 小規模事業者持続化補助金 등(사업자 대상) / 児童手当, 出産育児一時金 등(개인 대상 제도, 보조금과 별도 체계) | 各省庁, jGrants 포털 | 공모 단위(연 수회) |
| **광역자치단체(都道府県)** | 都道府県 독자 상공정책・육아지원 상승분 | 각 도도부현 공식사이트 | 연도 단위 |
| **기초자치단체(市区町村)** | 出産祝い金, 子育て世帯 住宅補助, 移住支援金 등 **지역차가 가장 큰 계층** | 각 시구정촌 공식사이트(전국 약 1,700여 개) | 예산연도・수시 |

**독자가 실제로 원하는 것은 3번째 계층(기초자치단체)이지만, 정보가 가장 파편화되어 있다.** 이 파편화를 얼마나 메우느냐가 사이트의 핵심 가치이자 확장 로드맵이다(§8 참조).

### 2.2 경쟁 지형

| 유형 | 특징 | 약점(= 우리의 진입 틈) |
|---|---|---|
| 지자체 공식 사이트 | 정확하지만 자기 지역만, 검색성 낮음 | 비교 불가, UI 낙후 |
| jGrants 포털 자체 | 공식・신뢰도 최상, API 공개 | 국가 사업자 지원금 중심, 개인 대상 제도・지자체 독자 시책 커버 약함, UX가 「해설」이 아닌 「목록」 |
| 士業(행정서사・노무사・중소기업진단사) 사무소 블로그 | 실무 지식 있음 | 자기 사무소 집객이 목적이라 특정 분야・지역 편중, 비교 관점 부족 |
| 대형 정보 포털(마이나비 등 부업/창업 매체) | 트래픽 큼 | 보조금은 부차 콘텐츠, 깊이・최신성 낮음 |
| 지역 이주(移住) 전문 매체 | 이주지원금 깊이 있음 | 육아・창업 등 타 분야 없음, 전국 커버 아님 |

**결론**: 「전국 커버 × 지역 비교 × 공식 API 기반 최신성」을 동시에 만족하는 플레이어가 없다.

### 2.3 일본어 SEO 환경

- **키워드 구조**: `補助金 一覧` `助成金 とは`(빅) → `出産 祝い金 比較`(미들) → `渋谷区 出産 祝い金 いくら`(롱테일, 지역×목적)
- 롱테일 「지역×목적」 조합이 압도적으로 많다 — 시구정촌 수 × 카테고리 수만큼 잠재 페이지가 존재
- YMYL(금전 관련 정보)에 준하는 취급 필요 — 출처・갱신일 명시 필수
- GEO/LLMO 대응: 「〇〇市 출산 축하금은 얼마?」류 질의에 AI가 표 형식 답을 인용하기 쉬운 구조가 핵심 경쟁력

### 3.1 독자 세그먼트

| 순위 | 세그먼트 | 특징 |
|---|---|---|
| **1** | 일반 개인・가구 (출산・육아・이사・주택・고령복지 등 생활 관련 보조금 탐색자) | 볼륨 최대, 지역 이동・생애주기 이벤트마다 재방문 가능성 |

| 3 | 이주 검토자(移住検討者) | 지역 비교가 가장 강하게 요구되는 세그먼트, 이주지원금 축과 직결 |

### 3.2 페르소나 카드 (신규)

**P1. 佐藤 さくら (31세, 도쿄도 스기나미구, 임신 6개월)**
- 검색어: `出産 祝い金 東京` `杉並区 出産 助成` `妊婦健診 補助 いくら`
- 원하는 것: 지금 사는 구와 이웃 구를 비교해서, 이사할지 말지 판단할 근거
- 우리의 답: 지역별 비교표 + 신청 체크리스트

**P2. 田中 建太 (29세, 지방 도시 창업 준비 중)**
- 검색어: `創業 補助金 2026` `小規模事業者持続化補助金 対象` `移住 起業 支援金`
- 원하는 것: 국가・광역・기초자치단체 지원금을 합산했을 때 총액이 얼마인지
- 우리의 답: 국가+지자체 지원금 합산 시뮬레이션형 콘텐츠

**P3. 山田 良子 (58세, 부모 개호 시작, 지자체 개호 보조 탐색)**
- 검색어: `介護 リフォーム 補助金` `〇〇市 高齢者 助成`
- 우리의 답: 개호・고령복지 카테고리의 지역별 비교

## 4. 정보구조(IA) — 요지

상세는 `docs/01_IA_TAXONOMY.md` v2 참조. 핵심만 요약한다.

```
/                          톱: 최신 공모・지역 선택 진입점
/subsidy/[category]/       카테고리별 허브 (예: /subsidy/shussan/ 출산・육아)
/subsidy/[category]/[slug] 개별 보조금 해설 기사
/area/[pref]/[city]/       지역별 허브 — 그 지자체가 제공하는 全카테고리 보조금 목록
/compare/[topic]/          지역 비교 페이지 (예: 「출산 축하금 전국 비교」) ★가장 강력한 SEO 자산
/news/                     신착・마감임박・개정 속보
/tools/                    자가진단・시뮬레이터
/data/                     자료실(서식・통계)
```

**설계 요지**: 카테고리(목적별)와 지역(지자체별)이라는 **두 개의 축이 직교**한다. 하나의 보조금 기사는 카테고리에 속하면서 동시에 지역 페이지・비교 페이지에서 인용된다. 이 이중 구조가 v1의 「독자 유형별 섹션」 구조를 대체한다.

## 5. 콘텐츠 전략 — 요지

상세는 `docs/04_EDITORIAL_GUIDELINE.md`・`docs/05_CONTENT_CALENDAR.md` v2 참조.

### 5.1 초기 카테고리(다분야 동시 착수)

카테고리 구조는 처음부터 폭넓게 설계하되, **각 카테고리는 Pillar 1개 + Cluster 3개 이상을 동시에 낼 수 있을 때만 신설**한다(v1의 카테고리 신설 규칙 유지). 초기 카테고리 후보는 `docs/01_IA_TAXONOMY.md` §3 참조.

### 5.2 콘텐츠 타입

| 타입 | 목적 |
|---|---|
| **비교(Compare)** | 같은 목적의 보조금을 지역 횡단 비교 — ★신설, 가장 중요한 신규 콘텐츠 유형 |
| **Pillar 가이드** | 카테고리별 종합 가이드 |
| **Cluster 해설** | 개별 보조금・제도 해설 |
| **속보(News)** | 신규 공모・마감임박・조건 변경 |
| **체크리스트** | 신청서류・조건 요약, 리드 획득 |
| **Tool** | 자가진단(받을 수 있는 보조금 찾기), 시뮬레이터 |

### 5.3 편집 규범 요지

- 一次情報(관공서 공식 발표) 링크 없는 기사는 발행 금지 — v1 원칙 그대로 계승
- 금액・기간・조건은 출처와 기준일 병기, 모집 상태(募集中/締切/終了)를 명확히 표시
- 「반드시 받을 수 있다」류 단정 표현 금지 — 조건 충족 여부는 신청자 확인 사항임을 명시
- **개별 신청 대행・서류작성 대행을 시사하는 표현 금지**(§6 법적 포지셔닝 유지 항목)

## 6. 기술 아키텍처

### 6.1 스택 (v1에서 계승)

| 레이어 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 15 (App Router) | 유지 |
| 콘텐츠 | MDX 로컬 파일 | 유지 — 단, frontmatter 스키마는 보조금 도메인에 맞게 재설계(§6.2) |
| 스타일 | Tailwind CSS | 유지 |
| 데이터 연동 | **jGrants API**(`src/lib/sources/jgrants.ts`, `http.ts` — v1 자산 재활용) | 국가 보조금 자동 수집의 핵심 축 |
| 호스팅 | Vercel 또는 Xserver(기존 배포 라인 유지) | 도메인・배포 방식은 별도 결정 사항 |
| 분석 | GA4 + GSC + Clarity | 유지 |

### 6.2 콘텐츠 도메인 모델 재설계 (핵심 변경점)

v1의 frontmatter는 「제도 해설 기사」 단위였다. v2는 **보조금 제도 자체가 1급 엔티티**가 되어야 지역 비교・카테고리 허브가 동작한다. 상세 스키마 설계는 `docs/03_CONTENT_TEMPLATE.md` v2에서 확정하되, 핵심 방향은 다음과 같다.

- 기사(해설 콘텐츠)와 별개로 **보조금 레코드**(제공주체, 대상지역, 금액, 마감일, 조건, 신청처 URL)를 구조화 데이터로 관리
- 지역 코드는 **전국地方公共団体コード**(총무성 표준, 5자리)를 기초 식별자로 채택 — 도도부현・시구정촌 어느 레벨에서도 일관되게 참조 가능
- 카테고리는 v1의 8대 업무분야 대신 **생활・사업 목적별 분류**로 재설계(`docs/01` §3)

### 6.3 v1 자산 처리 방침

| 자산 | 처리 |
|---|---|
| `content/` 전체(행정서사 기사 76건) | **삭제.** 주제 자체가 무관하므로 재활용 불가. git 이력으로 복원 가능 |
| `prompts/`, 자동발행 파이프라인(`docs/16`), 진단툴(`/tools/eiju-shindan`, `/tools/visa-navi`) | **삭제.** 행정서사 도메인 특화 로직 |
| `src/lib/sources/jgrants.ts`, `http.ts` | **보존・재활용.** 도메인 무관한 국가 보조금 API 연동 인프라 |
| `src/lib/sources/egov-law.ts`, `pubcomment.ts`, `kanpo.ts`, `jp-number.ts` | 개별 판단 — 법령 조문 취득(egov-law)・관보(kanpo)는 보조금 제도 근거법 확인에 계속 쓰일 수 있음. `jp-number.ts`(법인번호)는 사업자 대상 보조금 검증에 재활용 가능. 코드 정리 단계에서 재검토 |
| `taxonomy.ts`, `content-schema.ts`, `site.ts` | **전면 재작성.** 본 문서 §4, §6.2 방향에 맞춰 다음 세션에서 진행 |
