# 편집 규범 (Editorial Guideline)

> 상위 문서: `00_MASTER_PLAN.md` §5.3 / 법적 사항은 `06_LEGAL_COMPLIANCE.md`

## 1. 편집 철학

> **「一次情報にあたる」ことだけが、我々の唯一の武器である。**

현직 행정서사는 실무 경험이 있지만 시간이 없다. 예비교는 시험은 알지만 실무를 모른다.
우리가 이길 수 있는 유일한 지점은 **관보·퍼블릭코멘트·운용요령 원문을 끝까지 읽고, 그것을 남보다 빨리, 정확하게 풀어내는 것**이다.

## 2. 절대 규칙 (위반 시 발행 불가)

| # | 규칙 |
|---|---|
| R1 | **一次情報 링크(`legalBasis`)가 0건인 기사는 발행 금지.** zod 스키마가 빌드를 막는다. |
| R2 | 제도 상태를 `noticeLevel`로 정확히 구분한다. 「改定案」을 「決定」처럼 쓰지 않는다. |
| R3 | 금액·기간·요건 수치에는 **출처와 기준일**을 병기한다. |
| R4 | 추측은 「〜と考えられます（※編集部の推測です）」처럼 **추측임을 명시**한다. |
| R5 | 「必ず」「確実に」「100%」 등 결과 보증 표현 금지. |
| R6 | 개별 사안에 대한 조언·수임 유도 표현 금지 (→ `06_LEGAL_COMPLIANCE.md`). |
| R7 | AI 생성 초고는 **반드시 원문 대조 후** 발행. 원문 대조 없는 발행 금지. 자동 발행 시의 대조 주체·사후 검수는 §7 개정(2026-09-03) 참조. |
| R8 | 인용은 인용 요건(주종관계·출처명시·개변 없음)을 지킨다. |

## 3. 문체 규정 (일본어)

### 3.1 톤앤매너 — 독자층별

| 독자 | 문체 | 예시 |
|---|---|---|
| **一般個人** | です・ます체, 전문용어는 반드시 括弧로 풀이 | 「在留資格（いわゆる「ビザ」）とは…」 |
| **企業担当者** | です・ます체, 결론 우선, 표·체크리스트 다용 | 「結論から言えば、2027年3月までに◯◯が必要です。」 |
| **現役行政書士(Pro)** | だ・である체 허용, 조문 번호·항번 직접 인용 | 「入管法第22条第2項第1号の解釈として…」 |

### 3.2 공통 스타일

- **1문 60자 이내**, 1단락 3문 이내
- 결론을 먼저 (PREP: Point → Reason → Example → Point)
- 見出し는 H2/H3만 사용 (H4 이하 금지 — 목차 가독성)
- 한자·가나 균형: 「出来る」→「できる」, 「事」→「こと」 등 히라가나 우선
- 숫자는 반각, 단위는 「円」「ヶ月」 통일
- 「〜させていただきます」 등 과잉 경어 금지 → 「〜します」

### 3.3 한국어 화자가 자주 내는 부자연스러움 (자가 체크)

| ❌ 부자연 | ✅ 자연 |
|---|---|
| 〜することができます (남발) | 〜できます |
| 非常に重要です | とても重要です / 重要です |
| 〜に対して (조사 오용) | 문맥에 맞는 に / へ / について |
| 必要な書類は下記のようです | 必要な書類は次のとおりです |
| 〜と思われます (근거 없이) | 〜とされています（출처 명시） |

> 발행 전 **소리 내어 읽기**. 걸리는 곳이 있으면 부자연스러운 것이다.

## 4. SEO / GEO 작성 규칙

### 4.1 타이틀

- **32자 이내** (일본어 검색결과 절단 방지)
- 구조: `主軸KW｜差別化要素・年号`
- 예: `永住許可ガイドライン改定案とは｜2026年8月公表・変更点を全解説`
- 숫자·연도를 넣는다 (CTR 상승 + 신선도 시그널)

### 4.2 description

- 50~160자. **결론을 먼저 쓰고**, 읽을 이익을 명시
- 주력 KW를 앞쪽 40자 안에 포함

### 4.3 본문 구조

```
リード(2〜3문)              ← 결론·정의를 여기에. ★AI 검색 인용 지점
「この記事の結論」 블록      ← 3행 요약
H2 1. 制度の詳細解説
H2 2. 実務上の注意点 (+ IT解決策 소단락 필수)
H2 3. 必要書類チェックリスト
H2 まとめ (표)
H2 よくある質問 (FAQ 3건 이상)
H2 編集長の一言
```

### 4.4 GEO(AI 검색) 대응 체크

- [ ] 첫 단락에 **정의문**이 완결된 형태로 있는가 (「◯◯とは、〜のことです。」)
- [ ] FAQ 3건 이상, 각 답변이 **단독으로 인용 가능한 완결문**인가
- [ ] 비교·요건은 **표**로 되어 있는가 (AI가 파싱하기 쉬움)
- [ ] JSON-LD `FAQPage` / `Article`이 출력되는가
- [ ] 「2026年8月時点」 등 **기준일 명시**가 있는가

### 4.5 내부 링크

- Cluster → Pillar: **본문 상단 1회 + 말미 1회** 필수
- Pillar → 전 Cluster: 목차 형태로 나열
- 관련 기사는 `relatedSlugs`에 3~5건
- **앵커 텍스트는 링크 대상의 내용을 그 자체로 설명하는 문구**로 쓴다 (기사 제목 또는 「◯◯の要件」식 명사구). 「こちら」「この記事」「詳しくは」 단독 링크 금지 — 검색엔진·AI 모두 앵커로 대상을 이해한다

## 5. 품질 게이트 (발행 전 최종 체크)

```
□ 一次情報 URL이 살아 있고 내용이 일치한다
□ 제도 상태(施行済/改定案/施行予定)가 정확하다
□ 금액·기간·요건 수치가 원문과 일치한다
□ 법적 리스크 표현이 없다 (06_LEGAL_COMPLIANCE §4 체크리스트)
□ 결과 보증 표현이 없다
□ 일본어가 자연스럽다 (소리 내어 읽기 완료)
□ frontmatter 필수 필드가 전부 채워졌다
□ FAQ 3건 이상
□ 내부 링크 (Pillar 왕복) 설정 완료
□ OG 이미지 생성 완료
□ IT/DX 해결책 단락이 있다
```

## 6. 정정 정책

오류 발견 시:
1. **삭제하지 않는다.** 본문을 수정하고 `changelog`에 정정 사실을 기록한다.
2. 중대한 오류(요건·금액·기한)는 기사 상단에 정정 알림을 표시한다.
3. 정정 이력의 공개 자체가 E-E-A-T 시그널이 된다.

## 7. AI 활용 규범

| 공정 | AI 사용 | 사람 개입 |
|---|---|---|
| 一次情報 감시·요약 | ✅ 전면 | 최종 확인 |
| 아웃라인 작성 | ✅ | 조정 |
| 초고 작성 | ✅ | **필수 검수** |
| **수치·요건·조문 확인** | ❌ 금지 | **원문 대조 100%** |
| 일본어 교정 | ✅ | 최종 판단 |
| 발행 결정 | 🟡 조건부 자동 | **사전: 게이트 통과 필수 / 사후: 주 1회 전건 검수** |

> **AI가 만든 숫자는 전부 의심한다.** 조문 번호·금액·기한은 반드시 원문에서 직접 확인한다.
> 이 원칙 하나가 무너지면 YMYL 미디어로서의 생명이 끝난다.

> **§7 개정 (2026-09-03, 운영자 지시)**: 자동 발행 파이프라인(docs/16) 도입에 따라
> 「발행 결정은 사람만」을 「조건부 자동」으로 개정한다. 조건: ① 원문 취득 없는 인용 금지는
> 그대로 (자동 세션도 `npm run source`/`law` 취득분에서만 인용) ② zod·build 게이트 통과 실패 시
> draft 로 남기고 발행하지 않음 ③ **주 1회 `[auto]` 커밋 전건을 사람이 사후 검수** (문제 시
> §6 정정 정책 적용) ④ 중단 스위치는 docs/16 「운용」표. 이 개정 전 원칙(사람만)은
> 파이프라인을 중단하면 즉시 복원된다.
