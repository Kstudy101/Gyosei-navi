# 편집 규범 v2 (Editorial Guideline)

> 상위 문서: `00_MASTER_PLAN.md` §5 / 법적 사항은 `06_LEGAL_COMPLIANCE.md` v2
> v1(행정서사 종합미디어)의 편집 규범을 계승하되, 법 제19조 관련 항목을 제거하고 금전 정보(YMYL) 정확성 항목을 강화했다.

## 1. 편집 철학

> **「一次情報にあたり、地域で比較できる形に変える」ことが、我々の武器である。**

지자체 공식 사이트는 정확하지만 자기 지역만 다루고, 검색성이 낮다. 우리가 이길 수 있는 지점은 **파편화된 정보를 지역 횡단으로 비교 가능하게 재구성하고, 공식 API로 최신 상태를 유지하는 것**이다.

## 2. 절대 규칙 (위반 시 발행 불가)

| # | 규칙 |
|---|---|
| R1 | **출처 링크(`sourceLinks`)가 0건인 기사는 발행 금지.** zod 스키마가 빌드를 막는다(v1 R1 계승, 필드명만 변경) |
| R2 | 모집 상태(`subsidy.status`)를 정확히 구분한다. 마감된 것을 募集中으로 방치하지 않는다 |
| R3 | 금액・기간・조건 수치에는 **출처와 확인일(`subsidy.verifiedAt`)**을 병기한다 |
| R4 | 추측은 「〜と考えられます（※編集部の推測です）」처럼 추측임을 명시한다(v1 계승) |
| R5 | 「必ずもらえます」「確実に採択されます」 등 결과 보증 표현 금지 |
| R6 | **개별 신청 대행・서류작성 대행을 시사하는 표현 금지**(`06_LEGAL_COMPLIANCE.md` 참조 — v1보다 완화됐지만 이 한 줄은 유지) |
| R7 | AI 생성 초고는 반드시 원문 대조 후 발행. **원문(`data/sources/`)을 근거로 독자용 요약・재구성(문체 변환・표 정리・구조 재배열)은 허용**하되, 수치(금액・마감일・조건)와 제도 취지는 원문과 정확히 일치시킨다 — 임의 수치・취지 왜곡은 금지(AGENTS.md 절대규칙 7, 2026-09-20 개정) |
| R8 | 인용은 인용 요건(주종관계・출처명시・개변 없음)을 지킨다 |
| R9 | ★신규 — 데이터가 없는 지역・카테고리 조합은 `subsidy.status: unresearched`로 명시하고, **「보조금 없음」과 혼동되는 표현을 쓰지 않는다** |

## 3. 문체 규정 (일본어)

### 3.1 톤앤매너

v1은 독자 유형(일반/기업/전문가)별로 문체를 나눴으나, v2는 독자가 국적・재류자격과 무관한 일반 주민 전반이므로 **단일 톤으로 통일**한다.

- です・ます체, 전문용어는 반드시 括弧로 풀이(예: 「補助率（対象経費のうち補助される割合）」)
- 결론 우선(PREP: Point → Reason → Example → Point)
- 금액・조건은 **표**로 정리 — 문장보다 표를 우선

### 3.2 공통 스타일 (v1 계승)

- 1문 60자 이내, 1단락 3문 이내
- 見出し는 H2/H3만 사용
- 한자・가나 균형: 히라가나 우선
- 숫자는 반각, 단위는 「円」「ヶ月」 통일
- 과잉 경어 금지 — 「〜させていただきます」 → 「〜します」

### 3.3 한국어 화자가 자주 내는 부자연스러움 (v1 계승)

| ❌ 부자연 | ✅ 자연 |
|---|---|
| 〜することができます (남발) | 〜できます |
| 非常に重要です | とても重要です / 重要です |
| 必要な書類は下記のようです | 必要な書類は次のとおりです |
| 〜と思われます (근거 없이) | 〜とされています（출처 명시） |

> 발행 전 소리 내어 읽기.

### 3.4 AI 생성 특유의 부자연스러움 (v2 신설)

> 출처: `github.com/coji/natural-japanese`(MIT License) 스킬의 카탈로그를 편집가이드용으로 요약. AI가 초고를 쓰는 이 프로젝트의 파이프라인 특성상, §3.3(한국어 화자 특유의 오류)과 별개로 **AI 특유의 번역투·상투구**도 별도 점검이 필요하다. 원본은 137편 인간 작성 vs 406편 AI 생성 텍스트 코퍼스로 검증됨.

**영어 통사구조 직역투** — 일본어 문법상 틀리지 않지만 영어를 그대로 옮긴 티가 나는 패턴:

| ❌ 직역투 | ✅ 자연 |
|---|---|
| この事実は〜を示している（무생물 주어+타동사） | この事実から〜と分かる |
| 〜することによって、〜が上がる（by ~ing 직역） | 〜すると、〜が上がる |
| 〜という観点から見ると | 〜で見ると |
| このプロジェクトにとって〜が不可欠だ | このプロジェクトは〜が決め手になる |
| この決定は大きな意味を持つ（have의 직역） | この決定には大きな意味がある |
| 〜であることは間違いない | （근거를 먼저 쓰고 자연스럽게 단정） |
| ——つまり〜——（em-dash 이중 삽입구） | （）로 바꾸거나 문장을 나눈다 |

**AI 상투구·결론 강요형** — 빈도와 맥락이 문제이므로 기계적 전건 금지보다 「과용하지 않는다」는 원칙으로 적용:

| 카테고리 | 예시 |
|---|---|
| 결론 강요 | 「と言えるでしょう」「のではないでしょうか」「まとめると」「いかがでしたか」 |
| 과잉 강조 | 「非常に重要」「極めて重要」「言うまでもなく」 |
| 공허한 도입 | 「さて、」「このように」「見ていきましょう」「深掘りしていきます」 |
| 면책성 얼버무림 | 「一概には言えません」「〜という側面もあります」 |
| 공허한 형용 | 「不可欠」「核心的」「多角的」「包括的」 — 구체적 근거 없이 강조 느낌만 얹는 말 |
| 프레젠테이션식 숫자 선언 | 「理由は3つあります」로 시작해 억지로 3개로 정리 |
| 늘어지는 수식어 | 「近年、〜の重要性がますます高まっています」류의 뻔한 전제로 시작 |

이 목록은 **금지어 사전이 아니라 과용 감지용**이다. 단어 하나가 나왔다고 고치는 게 아니라, 같은 유형이 한 기사에 반복되면 손본다. 특히 보조금 기사는 결론(금액・마감)을 먼저 쓰는 구조(§4.3)이므로 「결론 강요형」 상투구가 끼어들 여지 자체가 적다 — 오히려 「공허한 도입」과 「프레젠테이션식 숫자 선언」이 체크리스트・비교 기사에서 나오기 쉬우므로 주의.

## 4. SEO / GEO 작성 규칙

### 4.1 타이틀

- 32자 이내
- 구조: `地域名＋制度名｜金額・締切などの差別化要素`
- 예: `渋谷区の出産祝い金はいくら？｜2026年最新の申請条件`

### 4.2 description

- 50~160자. 결론(금액 등)을 먼저

### 4.3 본문 구조

→ `03_CONTENT_TEMPLATE.md` §5 참조

### 4.4 GEO(AI 검색) 대응 체크

- [ ] 첫 단락에 정의문이 완결된 형태로 있는가(「〇〇とは、〜円を支給する制度です。」)
- [ ] FAQ 3건 이상, 각 답변이 단독 인용 가능한 완결문인가
- [ ] 비교・조건은 표로 되어 있는가
- [ ] JSON-LD `FAQPage` / `Article`이 출력되는가
- [ ] 기준일(`subsidy.verifiedAt`) 명시가 있는가

### 4.5 내부 링크

- Cluster(개별 보조금 기사) → Pillar(카테고리 가이드): 본문 상단 1회 + 말미 1회
- Cluster ↔ 비교 페이지(`/compare/`): 같은 주제의 타 지역 기사가 있다면 상호 링크 필수
- Cluster ↔ 지역 허브(`/area/[pref]/[city]/`): 같은 지자체 타 카테고리 기사로 링크
- 앵커 텍스트는 링크 대상을 그 자체로 설명하는 문구(「こちら」 단독 금지)

## 5. 품질 게이트 (발행 전 최종 체크)

```
□ 출처 URL이 살아 있고 내용이 일치한다
□ 모집 상태(subsidy.status)가 정확하다 — 마감 지난 것을 방치하지 않았다
□ 금액・기간・조건 수치가 원문과 일치하고 verifiedAt이 기입됐다
□ 개별 신청 대행을 시사하는 표현이 없다 (06_LEGAL_COMPLIANCE §4)
□ 결과 보증 표현이 없다
□ 일본어가 자연스럽다 (§3.3 한국어 화자형 부자연스러움 + §3.4 AI 상투구·번역투 과용 확인)
□ frontmatter 필수 필드가 전부 채워졌다 (subsidy 필드군 포함)
□ FAQ 3건 이상
□ 내부 링크 (카테고리・지역・비교 페이지 간) 설정 완료
□ OG 이미지 생성 완료
```

## 6. 정정 정책 (v1 계승)

오류 발견 시:
1. 삭제하지 않는다. 본문을 수정하고 `changelog`에 정정 사실을 기록한다.
2. 금액・마감・조건 오류는 기사 상단에 정정 알림을 표시한다.
3. 정정 이력의 공개 자체가 신뢰 시그널이다.

## 7. AI 활용 규범

| 공정 | AI 사용 | 사람 개입 |
|---|---|---|
| 一次情報 감시・요약 | ✅ 전면 | 최종 확인 |
| 아웃라인・초고 작성 | ✅ | **필수 검수** |
| **금액・조건・마감일 확인** | ❌ 금지 | **원문 대조 100%** |

| 발행 결정 | 사람(자동 파이프라인은 재구축 후 별도 결정) | — |

> **AI가 만든 숫자는 전부 의심한다.** 금액・마감일은 반드시 원문에서 직접 확인한다. 이 원칙이 무너지면 금전 정보 미디어로서의 생명이 끝난다.
