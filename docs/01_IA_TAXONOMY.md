# 정보구조(IA) & 분류체계 v2 — 전국 보조금 정보 사이트

> **코드 정본은 `src/config/taxonomy.ts`.** 본 문서는 그 설계 의도와 운용 규칙을 설명한다.
> 둘이 어긋나면 `taxonomy.ts`가 우선하며, 본 문서를 즉시 갱신한다.
> 상위 문서: `00_MASTER_PLAN.md`. v1(행정서사 종합미디어) 시절의 IA는 폐기 — 8대 업무분야・`/guide`・`/practice` 구조는 더 이상 쓰지 않는다.

## 0. v1 → v2 핵심 변경점

| 항목 | v1 | v2 |
|---|---|---|
| 제1계층 | 독자 유형(`/guide` `/practice` `/exam`) | **목적별 카테고리**(`/subsidy/[category]`) **× 지역**(`/area/[pref]/[city]`)의 이중 축 |
| 핵심 신규 자산 | 없음 | `/compare/[topic]` 지역 횡단 비교 페이지 — 가장 강력한 SEO 자산 |
| 분류 기준 | 行政書士 8대 업무분야 | 생활・사업 목적별 분류(출산육아・주택이사・창업사업・고령복지・에너지환경・반려동물 등) |
| 지역 표현 | 태그 축(`tokyo` `osaka` 정도, Phase 2 이후 활성화 예정이었음) | **1급 구조**. 전국地方公共団体コード(총무성 표준 5자리)를 지역 식별자로 채택 |

## 1. 2축 구조 — 카테고리 × 지역

```
축1: 카테고리(목적)   출산育児 / 住宅引越し / 創業事業 / 高齢介護 / エネルギー環境 / ペット / …
축2: 지역(지자체)     전국地方公共団体コード 기준 — 都道府県 → 市区町村
```

하나의 「보조금」은 **카테고리 1개 + 지역 1개**에 속하는 레코드다. 이 레코드를 기초로:
- 카테고리 허브 페이지(`/subsidy/shussan/`)는 그 목적의 보조금을 **전국에서** 모아 보여준다.
- 지역 허브 페이지(`/area/tokyo/shibuya/`)는 그 지자체가 제공하는 **전 카테고리** 보조금을 모아 보여준다.
- 비교 페이지(`/compare/shussan-oiwaikin/`)는 같은 주제를 **지역 횡단으로 나란히** 비교한다.

이 3종 페이지가 서로 내부링크로 연결되어, 기사 1건을 여러 진입 경로에서 재사용하는 구조를 만든다.

## 2. URL 규칙

```
https://example.jp/subsidy/shussan/tokyo-shibuya-oiwaikin
                    │        │       └─ 로마자 케밥케이스 슬러그 (지자체명-제도명 형태 권장)
                    │        └─ 카테고리 코드 (taxonomy.ts와 일치)
                    └─ 섹션

https://example.jp/area/tokyo/shibuya/
                    │     │      └─ 시구정촌 슬러그
                    │     └─ 도도부현 슬러그
                    └─ 섹션

https://example.jp/compare/shussan-oiwaikin/
                    │        └─ 비교 주제 슬러그
                    └─ 섹션
```

| 규칙 | 내용 |
|---|---|
| 슬러그 | 영소문자・숫자・하이픈만. 일본어 URL 금지(인코딩 깨짐) — v1과 동일 |
| 지역 슬러그 | 도도부현은 로마자 정식명 약칭(`tokyo` `osaka` `aichi`), 시구정촌은 로마자화(`shibuya` `yokohama-shi` 등). **`src/config/regions.ts`(신설 예정)에서 코드-슬러그 매핑을 1곳에서 관리** |
| 연도 | 공모 회차가 있는 보조금은 슬러그에 연도 포함(`-2026`), 상설 제도는 미포함 |
| 변경 | 발행 후 슬러그 변경 금지. 불가피하면 `redirects.json`에 301 등록 — v1과 동일 |
| 계층 | 4계층 이상 금지 — v1과 동일 |

## 3. 카테고리 (목적별 분류) — 초안

> **다분야 동시 착수** 방침에 따라 처음부터 폭넓게 설계한다. 단, 실제 신설(디렉토리 생성 + 라우트 추가)은 **Pillar 1개 + Cluster 3개를 동시에 낼 수 있을 때만** 한다(§6 확장 규칙). 아래는 카테고리 코드・범위의 설계 초안이며, `taxonomy.ts` 작성 시 확정한다.

|---|---|---|---|

| `jutaku` | 住宅・引越し | 주택리폼 보조, 이주지원금, 공영주택 관련 | 지역차 매우 큼 — 비교 페이지 효과 큼 |
| `sogyo` | 創業・事業 | 창업보조금, 사업재구축, 소규모사업자지속화 등 | jGrants 커버리지 가장 높음 — 초기 우선 후보 |

## 4. 지역 축 — 데이터 모델

### 4.1 지역 식별자

- **1급 식별자**: 総務省 전국地方公共団体코드(5자리 숫자, 예: 東京都渋谷区 = 13113)를 채택. 이유: 지자체명 변경・합병에도 코드는 안정적이며, 국가 통계・jGrants 등 외부 데이터와 매칭하기 쉽다.
- **표시・URL용**: 코드에 대응하는 로마자 슬러그를 `src/config/regions.ts`(신설 예정)에서 관리.
- **계층**: 都道府県(47) → 市区町村(약 1,700여) 2단.

### 4.2 커버리지 원칙 — v1 절대규칙 6과 동일하게 「0건≠미조사」

전국 1,700여 지자체를 한 번에 커버할 수 없다. 따라서:
- 카테고리×지역 조합에 데이터가 **없는 것**과 **아직 조사 안 한 것**을 코드 레벨에서 구분한다(예: `unresearched` vs `no-subsidy-found`).
- 지역 허브 페이지에 아직 조사되지 않은 지자체가 있다면 「미조사」임을 명시하고, 「보조금 없음」으로 오인되지 않게 한다.
- 이 구분 필드는 `docs/03_CONTENT_TEMPLATE.md` v2 스키마 설계 시 반영한다.

## 5. 비교 페이지(`/compare/`) — 신규 핵심 자산

v1에는 없던 개념. 카테고리와 지역의 교차점에서 가장 검색 수요가 높은 주제를 골라, **여러 지자체를 표로 나란히 비교**하는 페이지.

```
【비교 페이지 예시】 出産祝い金 東京23区 比較
   │
   ├─ 표: 区名 | 金額 | 所得制限 | 申請期限 | 申請先リンク
   ├─ 상위 링크: 어느 카테고리 허브(`/subsidy/shussan/`)에도 속함
   └─ 하위 링크: 각 지자체 개별 기사(`/subsidy/shussan/tokyo-shibuya-oiwaikin`)로
```

**규칙**: 비교 페이지 1개는 최소 지자체 5곳 이상의 데이터가 갖춰졌을 때만 발행한다. 데이터가 부족한 비교표는 신뢰를 해친다.

## 6. 확장 시 규칙 (v1 계승)

- 새 카테고리 추가 = `taxonomy.ts` 수정 + `content/subsidy/[category]/` 디렉토리 생성 + 본 문서 갱신, **3개 동시**
- 카테고리 신설 조건: **Pillar 1개 + Cluster 3개를 동시에 낼 수 있을 때만.** 빈 카테고리는 만들지 않는다.
- 새 지역 추가(시구정촌 데이터 확보) = `regions.ts`에 등록 + 최소 1개 카테고리 데이터 확보 시점에 지역 허브 페이지 생성

## 7. 특집(`/tokushu/`) — 편집적 랭킹 콘텐츠 (2026-09-20 신설)

`/compare/`(§5)가 **객관적 사실을 표로 나란히 놓는** 페이지라면, `/tokushu/`는 그 데이터를 근거로 **편집부가 순위・결론을 매기는** 페이지다. 예: 「子育てに手厚い市 TOP5」「移住支援が手厚い自治体 TOP5」.

```
【특집 예시】 子育てに手厚い市 TOP5
   │
   ├─ 편집부의 순위 매김 + 각 순위별 근거 서술
   ├─ 순위 산정에 쓰인 개별 지자체 기사로 링크(`/subsidy/shussan/...`)
   └─ 같은 주제의 `/compare/` 페이지가 있다면 상호 링크(비교표 ↔ 순위 해설)
```

### 7.1 발행 전제조건 — DB(표본) 부족 시 발행 금지

특집은 **비교 대상 지자체의 데이터가 최소 5개 이상(`/compare/`와 동일 기준, §5) 축적된 카테고리에서만** 만들 수 있다. 데이터가 부족한 상태에서 순위를 매기면 근거 없는 편집적 판단(추측 랭킹)이 되어 R1(출처 필수)・R4(추측 명시) 원칙을 위반한다. `docs/00_MASTER_PLAN.md` 단계상, 지역 데이터가 얇은 초기에는 **카테고리 구조만 선반영하고 실제 특집 콘텐츠는 표본이 쌓인 뒤 작성**한다.

### 7.2 카테고리 축

특집의 카테고리는 `subsidy`의 목적별 카테고리(§3)와 **별도 체계**다 — 특집은 「무엇을 랭킹 매길 것인가」라는 편집 테마이므로, 여러 subsidy 카테고리를 가로지를 수도 있다(예: 「子育てに手厚い市」는 `shussan`+`kaigo` 데이터를 함께 참조할 수 있음). `taxonomy.ts`의 `TOKUSHU_CATEGORIES`에서 관리하며, **향후 지속적으로 카테고리를 추가**하는 것을 전제로 설계한다(카테고리 신설 규칙은 §6과 동일하게 준용 — 단, 특집은 Pillar/Cluster 대신 「발행 가능한 순위 콘텐츠 1건」이 신설 조건).

### 7.3 URL 규칙

```
https://example.jp/tokushu/kosodate/kosodate-teatsui-shi-top5
                    │        │        └─ 로마자 케밥케이스 슬러그
                    │        └─ 특집 카테고리 코드
                    └─ 섹션
```

§2의 공통 슬러그 규칙(로마자・4계층 이내)을 그대로 따른다.
