## 한 줄 결론

**처음엔 “팔 서비스”가 아니라 “안전한 정보 미디어 + 내가 쓰는 도구”로 가라.**  
회원가입·직접결제·개인정보 수집은 뒤로 미루고, 콘텐츠·신뢰·간접수익부터.

---

## 1. 사이트·수익 모델 (≈1:01 / 3664s 핵심)

| 영상에서 강조 | 우리 사이트에 적용 |
|---|---|
| 회원가입·비밀번호 수집 금지 | 계정 없이 기사·가이드 전부 열람 |
| 유료 구독·판매부터 하지 말 것 | Phase A는 정보 제공만 (행정서사법 제19조와도 맞음) |
| 간접 수익으로 시작 (AdSense·제휴) | 광고·제휴는 나중에, **고지문 필수** |
| 인증·결제·DB는 전문 서비스 | 나중에 필요하면 Clerk / PG / Supabase 등 — **직접 구현 금지** |

**홈에 넣을 태도:** “지금 당장 팔지 않는다. 신뢰를 쌓는다.”

---

## 2. 보안·운영 (처음부터)

- 시크릿·API 키 **하드코딩 금지** → 환경변수만
- Cloudflare 등 **CDN·방어 레이어**
- Vercel처럼 **롤백 가능한 배포**
- 작게 공개 → 직접 써보기 → 피드백 → 확장 (MVP)
- 기능 무한 추가보다 **버전 끊고 멈추는 시점** 정하기

이미 마스터 플랜의 “Phase 0 → 콘텐츠 축적”과 같은 방향.

---

## 3. 콘텐츠·홈 구성에 옮길 원칙

1. **한 주제 장기 집중** — 「行政書士」 한 축으로 10년 갈 미디어. 이슈성 잡지는 수명 짧다고 명시.
2. **정보만 나열하지 말고 “쓰는 가치”** — 체크리스트·절차 가이드·용어집·계산/판정 보조 도구형 콘텐츠.
3. **데이터로 소재 고르기** — 감으로 양산하지 말고, 검색·관심·제도 개정 일정 기준으로 기사 우선순위.
4. **UX 우선** — 예쁜 UI보다 “들어온 사람이 한 번에 답을 찾는가”.
5. **투명한 고지** — 운영자·면책·광고/제휴(넣을 경우)·자격 상태. (`site.ts` 방향과 일치)

---

## 4. AI(바이브 코딩) 쓰는 방식

| 하라 | 하지 마라 |
|---|---|
| 초안·학습 보조·리팩터 검토 | “전부 AI에 맡기고 출시” |
| “왜 이 파일/구조인가” 질문하며 만들기 | 속도만 우선 |
| 문서화 + Git | 스파게티·기술부채 방치 |
| 본인이 먼저 써보고 공개 | 버그 많은 상태로 유료화 |

→ 이 프로젝트도 **미디어 본체가 상품**이고, AI는 작성·검증·자동화 도구.

## 기존 기획과 겹치는 점

마스터 플랜의 **무자격 기간 = 정보만 / 집객 자산 선구축**과 거의 같은 말.  
영상은 그걸 “보안·법·수익화 리스크” 언어로 다시 확인시켜 준다.

---

## 영상 전체 프레임 (참고)

1. **무엇을 했나**: WP 포스트 삭제 → AI로 웹앱·도구 다수 탑재 사이트 구축
2. **환상**: “말로 시키면 서비스가 되고, 바로 돈 된다”
3. **현실/위험**: 보안 구멍, 개인정보법, 스파게티 코드·기술부채, 장애 대응 불가, 마케팅 난이도
4. **안전한 로드맵** (≈1시간 전후): 회원가입·직접결제 금지 → 간접수익, 인증/결제/DB는 전문 서비스
5. **진짜 가치**: 판매용 SaaS보다 **나만의 생산성/콘텐츠 도구**, 철저한 개인화
6. **운영 태도**: AI는 도구·주인공은 사람, 호기심·검증·버전 끊기, 중독·번아웃 경계
7. **콘텐츠 비즈니스**: 주제 하나로 **장기(10년+)**, 이슈성 주제는 수명 짧음

## 주의

- 이 영상 ≠ 일본 士業 홈페이지 SEO 철칙 강의.
