## 2. 발동 즉시 — 원문 취득 (30분)

1. **結果公示物 취득** — 案件 페이지에 추가된 「意見公募の結果」 문서(의견 개요·考え方, 보통 PDF)와, 함께 게재되는 **확정판 본문**을 취득. 저장 위치는 `data/sources/pubcomment-3150001XX-result/` (README에 취득일·URL 기록):
   ```bash
   # HTML 페이지 (案件 상세페이지 등)
   npm run source -- --url <URL> --out data/sources/pubcomment-3150001XX-result/NN_<이름>.txt

   # PDF (結果公示物은 대부분 PDF — npm run source 는 PDF 를 명시적으로 거부한다)
   # ⚠️ 이 PC는 PDF 저장 직후 자동 암호화되므로 다운로드와 같은 셸 호출에서 즉시 추출까지 끝낼 것
   curl -sL -A "gyosei-navi-source-fetcher/1.0" -o /tmp/r.pdf "<PDF URL>" && pdftotext -layout /tmp/r.pdf data/sources/pubcomment-3150001XX-result/NN_<이름>.txt
   ```
   (pdftotext 는 poppler — 2026-08-23 설치 확인. 세로쓰기 PDF는 1자 1행으로 나올 수 있으나 내용은 유효 — 139의 新旧対照条文 선례)
2. **확정판 vs 改定案 差分 작성** — 갱신의 근거가 되는 핵심 산출물:
   - 개정안 정본: `data/sources/pubcomment-315000140/02_永住許可ガイドライン改定案.txt` (139는 `02_新旧対照条文.txt`, 141은 `02_永住者取消ガイドライン案.txt`)
   - 差分 결과를 `data/sources/pubcomment-3150001XX-result/DIFF.md`로 남긴다 (항번 단위: 第2の4(2) 등)
3. 확정판이 案件 페이지에 없으면 입관청 페이지(`nyukan_nyukan50.html` 등) 게재를 기다린다 — 감시가 잡아준다. **의견 考え方만 먼저 나온 경우도 §6의 뉴스 기사는 즉시 쓸 수 있다.**

| 이벤트 | noticeLevel 전환 | 비고 |
|---|---|---|
| 結果公示 + 확정판 공표 (改定日 확정) | `draft-proposal` → **`scheduled`** | 본문의 「改定案」 표현을 「改定後ガイドライン(令和8年◯月◯日改訂)」로. 개정일·적용일을 확정 날짜로 치환 |

2. **세대수입 기준 금액**(「日本人世帯の平均収入を上回る水準」의 구체 수치) 제시 여부
3. **受給年金水準・보전자산의 금액·산정식** 제시 여부
4. 수입 「継続して達している」의 **판단 기간**(몇 년분)
5. 개정안 문언 자체의 변경 유무 (의견 반영으로 조문이 바뀌었는가 — 差分으로 확인)

