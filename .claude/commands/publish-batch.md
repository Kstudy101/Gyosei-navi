사용자 입력(자유 텍스트, 대상 지역들・카테고리들・목적・발행 여부 등을 포함할 수 있음):

$ARGUMENTS

---

당신은 이 요청을 여러 개의 **orchestrator** 서브에이전트 호출로 분해해 병렬 실행한다. 직접 조사・집필하지 않는다.

## 절차

1. 사용자 입력을 읽고, 다뤄야 할 지역(도도부현/시정촌)과 카테고리 조합을 구체적으로 나열한다. 모호하면(예: "전국"처럼 과도하게 넓으면) 합리적인 범위로 좁히되, 좁힌 근거를 최종 보고에 명시한다.
2. `src/config/regions.ts`와 `content/subsidy/*/`를 확인해 이미 다뤄진 조합과 중복되지 않게 조정한다.
2-2. 사용자가 지역을 특정하지 않았거나 선택 여지가 있으면, **기사 수가 적은 도도부현을 우선**한다(`content/subsidy/*/`의 `subsidy.regionCode` 분포 기준). 도쿄 편중을 줄이고 전국 커버리지를 넓히는 것이 트래픽 전략이다 — 단, 이미 조사 자산(`data/sources/`)이 있는 지역의 미완 조합이 있으면 그쪽을 먼저 소화한다.
2-3. 카테고리에 **국가(전국) 제도의 pillar/cluster 기사가 부족**하면(해당 카테고리에서 `regionCode: "00000"` 기사 2건 미만), 배치 1건을 국가 제도로 배정하는 것을 검토해 사용자에게 제안한다. 국가 제도는 지역 제도보다 검색볼륨이 크고, 지역 기사들의 내부 링크 상위 허브가 된다.
3. 조합별로 **하나의 메시지 안에 여러 Task 호출을 담아** `orchestrator`를 병렬로 fan-out 호출한다. 순차 호출하지 않는다. 각 호출 프롬프트에는:
   - 해당 조합의 지역・카테고리
   - 사용자 입력 중 그 조합에 해당하는 맥락
   - "이것은 배치 작업의 일부다. 다른 조합과 독립적으로 완결하라."
   - 발행 여부 지시(사용자 입력에 명시가 있으면 그대로, 없으면 draft까지만)
4. 모든 orchestrator 결과가 도착하면 취합한다.

## 보고

배치 전체에 대해:
- 조합별 최종 상태(draft/published/실패) 표
- 실패하거나 원문을 확보하지 못해 skip된 조합과 이유
- 새로 생성된 `content/`, `data/sources/` 경로 전체 목록
- 새로 다룬 카테고리의 楽天アフィリエイト 매핑/상품 캐시 상태(신규 카테고리 매핑 추가 여부, API 키 미설정으로 캐시 생성이 보류된 경우 그 목록)
- 사용자가 다음에 확인/결정해야 할 사항

를 한국어로 간결하게 요약해 사용자에게 전달한다.
